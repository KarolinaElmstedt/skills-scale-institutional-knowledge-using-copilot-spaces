# OctoAcme Project Management Docs

This folder collects OctoAcme's project management process documents and provides a concise overview of how we plan, execute, and improve work across projects. Use this README as the single source of truth to discover the project initiation, planning, execution, release, risk, and retrospective guidance referenced by teams and stakeholders.

OctoAcme follows an iterative, data-informed delivery approach. Work begins with a lightweight Project One-pager to confirm the problem, expected outcomes, stakeholders, and success metrics. Approved initiatives move into planning where work is broken into shippable increments, acceptance criteria are defined, and a release/milestone plan is created. Execution happens in timeboxed iterations with regular demos and a close/retrospective phase to capture learnings and action items.

Day-to-day workflows use a project board (Backlog, Ready, In Progress, In Review, QA, Done) and disciplined pull request practices: small, reviewable PRs that link issues and acceptance criteria, automated CI and security scans prior to review, and at least one approval before merging. Sprint planning selects items that meet the Definition of Done and respect team capacity. Risk and dependencies are tracked in a lightweight Risk Register and reviewed in regular cadence meetings.

Roles and communication are explicit: Product Managers define outcomes and success metrics, Project Managers coordinate delivery and communications, Developers implement and test, QA validates acceptance, and Stakeholders provide inputs and approvals. Regular cadence includes daily standups for blockers and progress, weekly delivery syncs for status and risks, PM+PdM alignment meetings, and monthly stakeholder updates. Quality assurance is enforced via unit and integration tests, end-to-end smoke tests for critical flows, CI security scanning, manual QA as needed, and a release checklist with pre- and post-deploy verifications and rollback plans.
